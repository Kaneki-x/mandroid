# Android App Runner — project conventions

Read `docs/DESIGN.md` before changing anything architectural; `docs/PLAN.md`
holds the phase checklist and `docs/SPIKE-NOTES.md` the open measurements.

## Stack (fixed decisions)

- **Pure Swift**: AppKit for windows/input/menus, SwiftUI for setup, library
  and settings views. No Rust, no Electron, no third-party UI frameworks.
- **xcodegen** `project.yml` → `AndroidAppRunner.xcodeproj` (never edit the
  xcodeproj by hand; regenerate). Targets: `EmulatorKit` (framework, no
  AppKit UI), `AndroidAppRunner` (app), `EmulatorKitTests`.
- macOS 15.0 deployment target, Swift 6 language mode, hardened runtime in
  Release. Bundle ids `io.github.madeye.androidapprunner[.kit]`.
- SwiftPM dependencies: `grpc-swift-2`, `grpc-swift-nio-transport`,
  `grpc-swift-protobuf`, `swift-protobuf` only. No other packages without a
  documented reason in `docs/DESIGN.md`.
- gRPC code is **generated by `Scripts/gen-proto.sh` and committed** under
  `EmulatorKit/Generated/`. Do not use the `GRPCProtobufGenerator` build
  plugin. Re-run the script after changing `Protos/` and commit the output.
- Unzipping uses `/usr/bin/ditto -x -k`; APK entries via `/usr/bin/unzip -p`.

## Build, test, generate

```bash
xcodegen generate
xcodebuild -scheme AndroidAppRunner -configuration Debug build
xcodebuild -scheme AndroidAppRunner test          # unit tests (no emulator needed)
Scripts/gen-proto.sh                              # regenerate EmulatorKit/Generated
Scripts/integration-test.sh                       # needs a booted emulator; not CI
```

Before any push: `xcodegen generate && xcodebuild ... build && xcodebuild ... test`
must pass and `Scripts/gen-proto.sh` must leave a clean tree.

## Emulator facts that constrain the code

- **Max 3 secondary displays** per emulator (ids 1–3). `DisplaySlotPool` is
  the only place that allocates them.
- Display flags are always explicit: `1225` =
  `PUBLIC | OWN_CONTENT_ONLY | SUPPORTS_TOUCH | ROTATES_WITH_CONTENT | TRUSTED`.
  Never pass `0` (that turns on Android system bars).
- `setDisplayConfigurations` takes the **full** display set; omitted displays
  are deleted. Changing a size for an existing id resizes in place.
- `KeyboardEvent` has no display id; keyboard routing goes through
  `InputRouter`'s focus policy.
- Touch up events must send `pressure: 0` for the same identifier.
- Raise `maxResponseMessageBytes` (64 MiB) for `streamScreenshot`; the NIO
  transport default is 4 MiB.
- adb must be connected before adding displays (guest service starts over adb).

## Environment isolation (never touch the user's SDK)

All spawned `emulator`/`adb` processes get:
`ANDROID_SDK_ROOT`/`ANDROID_HOME`, `ANDROID_AVD_HOME`, `ANDROID_EMULATOR_HOME`
under `~/Library/Application Support/AndroidAppRunner/`, and a dedicated
`ANDROID_ADB_SERVER_PORT`. The reference SDK at
`/Volumes/DATA/workspace/android` is for the Phase 0 spike only.

## Git

- Never commit on `main`; branch as `feature/…`, `fix/…`, `docs/…`.
- Commit generated code and fixtures; do not commit downloaded SDK bits,
  `.build/`, or the xcodeproj's user data.
